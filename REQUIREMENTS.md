# Requirements and preservation contracts

## Authority and interpretation

This document extracts **explicit** rules from [AGENTS.md](AGENTS.md), not user requirements inferred from implemented UI controls, test names, or old reports. `AGENTS.md` remains the authoritative text; the links below identify its sections. If source and contract differ, record the divergence in the [audit findings](PROJECT_STATE_EOD_CHARTING_PLATFORM.md#unresolved-findings) instead of silently changing either. ## Engineering and operational requirements

- **Source authority and boundaries:** inspect current files first; maintain active Tauri 2, React/TypeScript, Rust paths, preserve accepted behavior, and exclude generated, dependency, database, backup and archive trees unless the task explicitly targets them. [AGENTS — Start](AGENTS.md#start), [Repo boundaries](AGENTS.md#repo-boundaries), [Context limits](AGENTS.md#context-limits).
- **Small changes and provenance:** restrict changes to the requested files, protect dirty worktree changes, apply scoped backup rules unless explicitly prohibited, and maintain owner-specific documentation and handoffs after implementation. [AGENTS — Change discipline](AGENTS.md#change-discipline).
- **Cargo artifacts and release safety:** use the shared Cargo wrapper, preview before approved compilation, serialize Cargo runs, and do not create new targets, installer or portable builds without authorization. [AGENTS — BUILD-01](AGENTS.md#build-01-shared-cargo-artifact-policy).
- **Scratch/evidence retention:** use exact marked disposable workspaces and documented lifecycle rules; do not mass-delete evidence. For PowerShell evidence packaging use the dynamic `Join-Path $HOME 'Downloads'` destination. [AGENTS — TMP-01](AGENTS.md#tmp-01-disposable-scratch-workspace-retention-policy).
- **Validation truthfulness:** use relevant validation profiles and focused tests; never call a check successful without its actual exit result. Leave routine portable Windows rebuild to the user. [AGENTS — Validation](AGENTS.md#validation).

**Boundary:** Feature presence is not by itself a new product requirement. Consult [Feature status](FEATURE_STATUS_MATRIX_EOD_CHARTING_PLATFORM.md) for observed capabilities and the [audit baseline](PROJECT_STATE_EOD_CHARTING_PLATFORM.md) for unanswered contract-vs-source questions.
