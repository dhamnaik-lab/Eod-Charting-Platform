## Implementation

- Explicit BSE Fetch collects the fixed official Active Equity identity-master CSV when local BSE instruments have blank codes. This also runs when requested CA dates are already cached. Load & Validate stays offline.
- Reuses the existing HTTP-to-isolated-WebView2 transport, cancellation, exact-request/resource restrictions, response byte limit and immutable SHA-256 capture receipts. The collector permits only the exact additional master endpoint; it is not a generic browser fetch. Master schema and minimum population are checked before use. Direct endpoint access returned HTTP 403 in a bounded probe.
- Fills blank codes only when official ticker and full ISIN both exactly match a unique local BSE instrument. Conflicting source codes, tickers or ISINs, local shared ISINs and already-claimed codes remain blocked. Even malformed source observations participate in conflict detection. Existing codes, NSE records, names, lifecycle flags and quotation data are not changed.
- During normal classification preparation, evidence-backed unmatched `BSE_API` rows in `UNRESOLVED`, `NEEDS_REVIEW` or `UNSUPPORTED` status retry exact security-code resolution. Review/unsupported blocks are preserved when attaching identity metadata. Manual/protected/approved rows are preserved. Identity-only changes receive a `BSE_SECURITY_CODE_RESOLUTION` audit decision; original source evidence remains unchanged. Current master metadata is not event-date identity proof.
- Classic queue cells, sorting, detail headings and selection labels show `BSE <code> (unmatched)` when no symbol/ISIN is resolved. This label grants no readiness or approval.
