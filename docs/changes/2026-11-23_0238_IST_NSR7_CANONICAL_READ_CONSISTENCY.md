## What a canonical read depends on

The scanner's production source opens read-only SQLite connections and calls the EOD gateway. The gateway resolves an instrument through `instruments` and `instrument_identity_history`, determines its related symbols and settlement, reads the configured storage mode, and combines eligible binary and Hybrid rows. A newly created binary file can supersede Hybrid fallback. Identity, alias, storage-mode or binary changes can therefore change the canonical stream even if the file containing the SQLite database still has the same identity. The raw path also needs a real predecessor at page boundaries where the gateway uses it. ## Decision

Use a **cross-process per-database read and mutation lease** for the initial full numeric history capability. A scan holds a shared lease during canonical reads. A participating writer holds an exclusive lease across its complete mutation. This gives the forward cursor one stable set of canonical inputs without loading or copying the database into memory. It also creates a bounded period of writer contention. Finalize the lease hold budget and approve the user-visible busy behavior before enabling the capability.

- Key the gate by the verified canonical database folder identity in a coordination namespace shared by every supported participant. Equivalent paths must converge on the same lock and independent databases must proceed independently. Acquire the existing database-use permit for deletion protection. Resolve the selection and release the registry lock before trying to acquire the new lease. Revalidate the selection afterward. Avoid waiting for the new lease while holding a registry lock, SQLite transaction, cached connection lock or recovery lifecycle lock.
- Hold the scan lease before universe resolution and source reads, through final cursor exhaustion and the commit eligibility check. Use stable target identity, inclusive as-of bounds and canonical predecessor context. Bound the read and evaluation interval by the approved workload and deadline. Hold the lease through any outstanding reads after cancellation. Release it before a slow client starts pulling immutable result pages. Recheck selection for publication and result retrieval, with commit fenced against selection changes and cancellation.
- Lease the entire writer apply phase, beginning before its first integrity-sensitive read or mutation and ending after file workers, SQL commit and recovery bookkeeping. Perform network fetch and parsing outside this lease where the workflow permits. A nested operation or worker inherits the enclosing session's authority. Acquisition failure must happen before mutation and preserve retryability. The existing Bhavcopy worker caps, checkpoint and durability rules stay in effect.
- Make crash handling explicit. A released OS lock alone only proves the writer is gone. Persist a mutation intent before changing canonical inputs, or bind an equivalent existing durable journal to that lease. Clear it only after a known consistent finish or verified recovery. Dirty or unreadable coordination state makes full paging unavailable. Resume or repair through the owning recovery workflow. Classify deferred checkpoint states from evidence and keep any restore, truncate, append or rewrite under the mutation lease.
- Fail closed if a supported writer can bypass the gate, or if the deployment cannot establish a shared coordination namespace. Direct external file editors and old binaries that ignore the protocol are outside the guarantee. Require a coordinated deployment before advertising the new capability. A read-only SQLite transaction stabilizes SQLite reads only. The selection revision and file identity witness do not protect against row updates or in-place binary rewrites. The binary side index can publish verified rows without increasing its index generation. [Deletion permit](../../src-tauri-shell/src/database/database_use.rs) · [Selection witness](../../src-tauri-shell/src/database/connection_registry.rs) · [Binary state index](../../src-tauri-shell/src/database/eod_binary_state.rs).

A short SQLite snapshot plus per-page file metadata checks could miss an in-place write. An optimistic cross-store epoch would require marking every writer before its first mutation and handling partial commits and crashes. The selected lease has a simpler admission rule for the first version. Consider a different consistency mechanism only if the measured writer contention is unacceptable.

## First implementation boundary and acceptance

Implement the per-database coordination primitive and wire one representative dual-store writer, quote mutation, through a testable owner boundary. Exercise the scanner side using a disposable database fixture and a private reader. Keep the full-history capability disabled and leave existing V1 scans on the current path while enrollment is incomplete. The initial implementation must preserve quote-only deletion and the current partial-error contract. Recovery or reconciliation after an interrupted dual-store mutation must be designed before that writer is considered enrolled.

- Show reader/writer exclusion in the same process and across cooperating Windows processes, with path aliases converging and separate databases remaining independent. Exercise cancellation and deadline release, immediate retry, concurrent worker completion, busy behavior before mutation, stale owner or marker, and a simulated crash between SQLite and binary writes.
- Expand enrollment family by family. Inject Hybrid changes, existing-date in-place rewrites, binary creation replacing fallback, file removal or replacement, alias and settlement changes, storage-mode changes, replay, and A → B → A reselection during a scan. A run must either return the complete pre-mutation canonical stream or fail without committing results.
- Authorize exposing paging only after the writer inventory is closed, the canonical cursor matches full fixture reads for Binary and Hybrid, the lease duration and contention are measured, and cleanup leaves no publishable data after an abort. Use the existing [paging design matrix](2026-11-23_0152_IST_NSR7_NUMERIC_HISTORY_PAGING_DESIGN.md) for IPC and result-size acceptance.
