## Current behavior and feasibility

- Generic numeric V1 history evaluates each rule against the available prefix at each eligible endpoint. It selects the trailing 1,000 eligible endpoints from a read window of at most 5,000 bars. Per-rule coverage counts completed verdicts including no-matches and reports eligible omissions within that window. A full window makes older input unknown. Recomputing each growing prefix over full history would repeat work proportional to the square of the number of endpoints for a fixed AST. [Executor](../../src-tauri-shell/src/native_scanner/scan.rs) · [Coverage evidence](2026-11-23_0142_IST_NSR7_NUMERIC_HISTORY_COVERAGE_REPORTING.md).
- Prior fixtures verified exact numeric dates for 999, 1,000, 1,001, 5,000 and 5,001 input bars under today's cap. The separate pattern-only test verified that one Common Gap episode survives a 5,001-bar page seam with 260 bars of overlap. These fixtures establish the bounded baseline. [Continuity evidence](2026-11-23_0117_IST_NSR7_HISTORICAL_ENDPOINT_CONTINUITY.md).
- The numeric AST admits nested indicators, field lookbacks, crosses and three-valued logic. The request allows 32 rules, with depth 24, a shared 512-node request budget, periods through 400 and field lookbacks through 2,000. Stacked lookbacks and warm-up can exceed one 5,000-bar page. EMA and RSI retain state since their actual seed or latest reset. V1 ATR uses a simple moving average of true range, with previous close as input and high minus low for the first bar of the series. [Rust AST and evaluator](../../src-tauri-shell/src/native_scanner/ast.rs) · [TypeScript request contract](../../src/features/scanner/nativeScanContract.ts).
- The production source goes through the canonical database gateway. The standalone binary reader documents bounded trailing reads, but the production gateway also handles aliases, settlement and storage selection, date reconciliation and boundary padding. The unified loader reads bounded rows per related symbol before reconciliation. A new cursor must bound that intermediate work as well as the returned page. [Reader](../../src-tauri-shell/src/native_scanner/reader.rs) · [Database source](../../src-tauri-shell/src/native_scanner/database_source.rs) · [Canonical gateway](../../src-tauri-shell/src/database/eod_data.rs).
- V1 emits match batches from progress, retains target outcomes and aggregate matches in memory, and can send per-target coverage in one completion. The renderer also buffers provisional matches through terminal acceptance. Smaller events alone leave result residency proportional to match count. Both V1 request validators reject unknown fields. [Job and events](../../src-tauri-shell/src/native_scanner/job.rs) · [IPC](../../src-tauri-shell/src/native_scanner/ipc.rs) · [Scanner adapter](../../src/plugins/scanner/nativeScannerRun.ts).

## Proposed opt-in contract

1. Use a separately versioned and advertised desktop capability with its own start and page operations. Its initial contract accepts explicit canonical targets, an optional inclusive as-of date, raw prices, and 1–32 generic numeric rules within the current AST limits. Define full history as all canonical completed bars from the source's first available record through the cutoff captured at admission. Omit lookback and date-range options initially. Reject pattern and reserved Core/Daily Market rules, duplicate canonical targets and invalid requests before work. Keep V1 request parsing, commands, events and coverage semantics intact.
2. Traverse one verified canonical stream per target in ascending date order. Use a forward keyset cursor over the reconciled dates with a stable source cutoff and explicit exhaustion. Preserve canonical predecessor context. Context reads seed the evaluator and produce no duplicate verdicts. Each bar has one owner and advances each rule's state once. Use the existing structural warm-up threshold, clamped to one bar, as the first eligible ordinal. Retain the evaluator's null, coercion, comparison and truthiness semantics. Count every eligible verdict including false and undefined. A short-series rule completes with zero evaluated endpoints. Report source bounds and bar count separately from per-rule eligible bounds and counts.
3. Use the current single-series evaluator as the semantic oracle, with the existing per-endpoint prefix evaluator as a cross-check on selected cases. Lower the AST to bounded per-node state. Share a bounded OHLCV lag buffer across rules, retain previous operands for crosses, and retain optional inputs for SMA and volume SMA. Sum in the current window order to preserve threshold behavior. Carry EMA seed count, seed sum and current value, with a reset on undefined input. Carry RSI's previous input, seed gains and losses, and both smoothed averages, with its existing gap reset and zero-loss branch. Carry previous close and the true-range ring for ATR. Retain state across every page seam, including while nested children are still warming up. Compile and account for the rings before starting a run. Structural warm-up gates coverage and emission. Runtime nulls may persist or recur after that gate.
4. Evaluate once per eligible `(exchange, symbol, rule, trade date)` for a successful run, regardless of source page size or result retrieval retries. Publish only matches and separately paged coverage. Preserve deterministic match order by date descending, then exchange, symbol and rule ID. A bounded private result spool with an ordered index can stage the run and commit it after successful source exhaustion and identity checks. The terminal reply contains counts and readiness. Opaque run-bound page tokens replay the same immutable page while valid. Pull one bounded page at a time, with at most 1,000 records and a serialized byte limit per response. Page all potentially large payloads, including coverage or diagnostics. Keep the existing V1 1,000-endpoint cap as-is.
5. Start with one worker and one active run. Set explicit target, per-node state, source batch, work, response-byte and private spool limits before exposing the contract. Reject oversize input up front where possible. Exhaustion of a runtime quota fails explicitly and yields no committed results. Spool size and runtime can grow with input within those limits. RAM should be bounded by the configured source batch, AST state, result buffer and index cache, plus bounded target bookkeeping. Make result cleanup part of cancel/failure/expiry or explicit close, with startup recovery for abandoned temporary output. Fixture measurements must establish actual limits before admission. The current renderer pagination controls are separate.
6. Bind admission, reads and result retrieval to the registered database identity, activation revision and physical SQLite identity, and retain the database-use permit until the worker has exited. The existing permit protects against deletion. Long scans also need a source snapshot or a writer-coordinated monotonic generation covering canonical metadata, Hybrid rows and every contributing binary file, including in-place rewrites. Selection identity and seam checks alone cannot provide that consistency. Check the witness at bounded page or work checkpoints and at commit. Reject any invalidation, including A → B → A, source replace or rewrite, and canonical mapping changes. Recheck before serving committed pages. Cancel at reader and evaluator block boundaries and before commit, with one terminal outcome. A cancelled, invalidated or failed run exposes no results or coverage. Choose explicit failure when the source cannot support the required consistency.

Forward state evaluation is feasible with bounded memory. Native paging across the production database remains conditional on demonstrating the canonical cursor and a source consistency mechanism across SQLite and binary data. A trailing cursor with overlap supports the current pattern detector. Forward numeric evaluation requires the original seed history, which makes the pattern cursor unsuitable as a direct replacement.
